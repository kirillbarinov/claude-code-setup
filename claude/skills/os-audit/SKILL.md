# OS Audit — твой сетап всё ещё правда?

CLAUDE.md, индексы и списки скиллов — это **утверждения** о том, что существует и что
актуально. Аудит сверяет каждое утверждение с диском.

## Железные правила

1. **Read-only.** Никогда не чинить, не переименовывать, не удалять, не перемещать во время
   аудита. Ни одного `rm`, `mv`, `git commit`. Только чтение и отчёт.
2. **Фиксы — отдельным шагом, после явного «да».** Отчёт заканчивается fix-list'ом, сгруппированным
   по A/B/C/D. Пользователь говорит, что из этого делать.
3. **Не угадывать.** Если факт не удалось проверить — писать «не проверено» с причиной, а не
   правдоподобное предположение. Непроверенный факт в отчёте об ошибках — это сам по себе
   poisoning.
4. **Сегодняшняя дата обязательна.** Вся арифметика свежести считается от реальной даты, взять
   через `date +%F`.

## Область

По умолчанию: `~/.claude` (глобальный сетап) + `~/.claude/RTK.md`. Проектные `CLAUDE.md`
проверять, если они есть в рабочей папке.
Если передан аргумент — сузить до него и сказать об этом в шапке отчёта.

## Шаг 0 — прошлые отчёты

```bash
date +%F
ls -1t ~/.claude/audits/*.md 2>/dev/null | head -3
```

Если отчёты есть — прочитать свежий и работать **дельтой**: что починено с прошлого раза, что
осталось, что появилось нового. Если папки нет — создать `~/.claude/audits/` (единственная
запись на диск, которую аудит делает сам).

## Шаг 0.5 — масштаб

```bash
ls -1 ~/.claude/skills | wc -l; ls -1 ~/.claude/agents/*.md | wc -l; ls -1 ~/.claude/hooks | wc -l
```

Если скиллов больше сотни — **не тащить всё в один контекст** (файл на 2500 строк в субагенте =
autocompact thrashing). Развернуть по одному Explore-субагенту на проверку ниже, передав каждому
только его инструкцию и список путей, затем слить отчёты. Один субагент = одна проверка.

## Check 1 — Routing integrity: всё, на что сетап ссылается, существует?

Собрать все пути, упомянутые в `~/.claude/CLAUDE.md`, `~/.claude/RTK.md`,
`~/.claude/LEARNED.md`, и проверить каждый на диске.

```bash
# ~ засчитывается только со слэшем: «~20 мин» и «~800 КБ» из прозы — не пути.
# Globs раскрываются через find: в zsh переменная не глоббится, ls -d $e даёт ложный DEAD.
# OPTIONAL — пути-флаги: их отсутствие и есть норма, не поломка.
OPTIONAL='perplexity-guard.disabled|version-drift.md'
grep -ohE '(~/|/Users/[A-Za-z0-9._-]+/)[A-Za-z0-9._/*-]+' \
  ~/.claude/CLAUDE.md ~/.claude/RTK.md ~/.claude/LEARNED.md 2>/dev/null \
  | sed 's/[.,;:)]*$//' | sort -u | while read -r p; do
  e="${p/#\~/$HOME}"
  case "$p" in
    *[*?]*) [ -n "$(find "$(dirname "$e")" -maxdepth 1 -name "$(basename "$e")" -print -quit 2>/dev/null)" ] \
              && echo "OK   $p (glob)" || echo "DEAD $p (glob пуст)"; continue;;
  esac
  if [ -e "$e" ]; then echo "OK   $p"
  elif echo "$p" | grep -qE "$OPTIONAL"; then echo "--   $p (опциональный флаг, отсутствие = норма)"
  else echo "DEAD $p"; fi
done
```

Отдельно проверить опорные точки сетапа (они названы в правилах и от них зависит поведение):

| Путь | Зачем нужен |
|---|---|
| `~/.local/share/design-skills/LEARNED.md` | Куда отправлены грабли дизайн-цикла |
| `~/.claude/hooks/perplexity-guard.sh` | Принуждение «Воронки» |
| `~/.claude/perplexity-guard.log` | Журнал решений guard |
| `~/.claude/mcp` | Боевая локальная сборка perplexity-MCP |
| `__PYTHON__` | Рабочий python (не Xcode-заглушка) |

Проверить, что названные по имени скиллы и агенты существуют:

```bash
for s in research web-test archify artifact-diagramming os-audit; do
  ls -d ~/.claude/skills/$s >/dev/null 2>&1 || echo "СКИЛЛ НЕ НАЙДЕН (или он из плагина): $s"
done
for a in researcher web-test-runner security-auditor design-director design-critic; do
  [ -f ~/.claude/agents/$a.md ] || echo "АГЕНТ НЕ НАЙДЕН: $a"
done
```

Скилл может жить в плагине, а не в `~/.claude/skills` — тогда это не поломка. Проверить по
списку доступных скиллов, прежде чем помечать красным.

Проверить CLI-команды, на которые опираются правила:

```bash
for c in ezycopy rtk anydoc ffmpeg jq; do command -v "$c" >/dev/null || echo "КОМАНДА НЕ НАЙДЕНА: $c"; done
```

**Обратное направление:** крупные папки в `~/.claude`, не упомянутые нигде в правилах — потенциально
осиротевшие. Перечислить, не объявляя мусором: решает пользователь.

## Check 2 — Index truth: списки совпадают с диском?

Любое место, где сетап называет **количество** или **перечень** — сверить с фактом. Счётчик в
тексте, который никто не пересчитывает, — классический источник уверенно неверного ответа.

Сверить перечисления скиллов и агентов в CLAUDE.md с реальным содержимым папок. Расхождение в обе
стороны: названо, но нет на диске (фантом) и есть на диске, но нигде не названо (сирота).

Отдельно — **скилл загружается или только лежит на диске?** Каталог без валидного YAML-фронтматтера
с `name` и `description` Claude Code не индексирует: скилл невидим, ни ошибки, ни предупреждения.
Check 1 это не ловит — он проверяет существование каталога.

```bash
for f in ~/.claude/skills/*/SKILL.md; do
  head -1 "$f" | grep -q '^---$' || echo "НЕВИДИМ (нет фронтматтера): $(basename $(dirname $f))"
done
```

Найденный невидимый скилл сверить с правилами: если на него ссылается CLAUDE.md, это RED —
правило отправляет в маршрут, которого агент не видит.

## Check 3 — Freshness: версионные факты не протухли?

В Applied Learning и LEARNED.md лежат факты о версиях окружения. Они устаревают молча.

Сверку версий делает скрипт — не сверяй руками:

```bash
~/.claude/hooks/check-tool-versions.sh
cat ~/.claude/state/version-drift.md 2>/dev/null || echo "дрейфа нет"
```

Ожидания лежат в `~/.claude/state/versions.expected.json`, там же указано, в каком файле правил
заявлен каждый факт. Расхождение чинится **в двух местах сразу**: в файле правил и в манифесте.
Скрипт покрывает не всё — что не в манифесте (typescript, chrome-devtools и т.п.), проверь руками. Пометить
статусом: **fresh** — совпадает; **drifting** — версия сменилась, заметка ещё верна по сути;
**frozen** — заметка описывает состояние, которого больше нет; **retired** — инструмент удалён.

Возраст ключевых файлов:

```bash
for f in ~/.claude/CLAUDE.md ~/.claude/LEARNED.md ~/.local/share/design-skills/LEARNED.md; do
  [ -f "$f" ] && echo "$(stat -f '%Sm' -t '%F' "$f")  $f"
done
```

Отдельно: **cutoff в правиле поиска** (сейчас «май 2026»). Если он отстал от реальной даты больше
чем на полгода — поднять флаг: правило «полгода до — проверять» перестаёт покрывать разрыв.

## Check 4 — Hygiene: мусор рядом с живыми файлами

```bash
find ~/.claude -maxdepth 3 \( -name '*.bak*' -o -name '*.old' -o -name '*.disabled' -o -name '*.orig' \) -not -path '*/plugins/*' 2>/dev/null
```

Для каждой находки сказать, **чем именно она опасна**, а не просто перечислить:
- `*.bak` рядом с живым файлом в `agents/` или `skills/` — агент может прочитать бэкап как
  действующую инструкцию и выполнить устаревшее правило. Это poisoning.
- `*.disabled` в `hooks/` — принуждение, которое пользователь считает работающим, не работает.
  Проверить, отключено ли намеренно.
- Множественные бэкапы одного файла — указать, сколько их и какой самый старый.

## Check 5 — Bloat и дубли

- Скиллы с пересекающимися `description`. **Пересечение само по себе не находка** — сортировать
  по цене ошибки, иначе каждый аудит выдаёт один и тот же шум:
  - **Каталог вкусов** (дизайн-пресеты: glass / grid / laser / reveal-лейауты) — обязаны
    пересекаться, разница визуальная и словами не выражается. Выбрали не тот — поправили репликой.
    Цена нулевая, НЕ поднимать.
  - **Чужие файлы** (скиллы из плагинов, напр. gsd-*) — правка слетит при обновлении плагина.
    Называть, но не предлагать чинить описанием.
  - **Свои, на один триггер, с разным результатом** — единственный настоящий класс. Лечится
    строкой-развилкой «Не путать: это X. Для Y — такой-то скилл» в описании КАЖДОГО из пары.
  Внимание: описания на разных языках метрика пересечения не сводит. Русское и английское
  описание одного и того же триггера дадут ложное «дублей нет».
- Повторяющиеся правила внутри CLAUDE.md, сказанные разными словами в разных секциях.
- Заметки в Applied Learning / LEARNED.md, дублирующие друг друга или уже неактуальные.
- Размер того, что грузится в каждую сессию:

```bash
wc -c ~/.claude/CLAUDE.md ~/.claude/RTK.md 2>/dev/null
```

Назвать цифру в символах и напомнить: это постоянная плата за каждую сессию.

## Check 6 — Четыре режима отказа контекста

Прямо проверить сетап на каждый:

| Режим | Что искать в сетапе |
|---|---|
| **Poisoning** | Утверждение в правилах, противоречащее диску: «боевая сборка лежит там-то», а её там нет; путь в заметке, которого не существует; бэкап-файл, читаемый как инструкция |
| **Bloat** | Объём, грузящийся всегда, без учёта задачи; секции, нужные раз в месяц, но читаемые каждую сессию |
| **Confusion** | Правило, сформулированное так, что под него подходит и то, что не имелось в виду; отсутствующее правило там, где агент вынужден догадываться |
| **Clash** | Два правила, дающие противоположные указания. Типовой пример: одно правило запрещает инструмент, другое требует его же для частного случая — и не сказано, какое сильнее |

Clash искать особенно внимательно: он даёт плавающее поведение, которое невозможно
воспроизвести, и потому выглядит как «модель тупит».

## Check 7 — Liveness: маршрут ещё кто-то ходит?

Самый дорогой класс протухания. Ссылка резолвится, файл на месте, версия верна — а воркфлоу
мёртв: сервисом перестали пользоваться год назад, а правило осталось и продолжает грузиться в
контекст каждой сессии и направлять агента в пустоту.

Check 1 это **не поймает**: он проверяет, что путь существует, а не что по пути кто-то ходит.

Найди в правилах всё, что завязано на внешний сервис, аккаунт, API или чужую систему:

```bash
grep -rn -iE "notebook|obsidian|github|api[ _-]?key|token|mcp|cron|launchctl|аккаунт|подписк" \
  ~/.claude/CLAUDE.md ~/.claude/docs/*.md 2>/dev/null | cut -c1-160
```

Для каждого найденного — три вопроса, и ответ берётся с диска, а не из головы:

1. **Есть ли следы использования?** Когда в последний раз менялись файлы, которые этот воркфлоу
   производит? Если артефакты не трогали месяцами — кандидат в мёртвые.
2. **Жив ли канал?** Есть ли ещё MCP-сервер, ключ, бинарь, задача в `launchctl list`?
3. **Спросить пользователя.** Это единственный класс находок, который **нельзя** решить осмотром
   диска. Не удалять молча — вынести в отчёт отдельным разделом «Подтвердить: этим ещё пользуются?»
   и перечислить маршруты с датой последнего следа.

Проверить и обратное — что запланированные задачи реально стоят:

```bash
launchctl list | grep -i claude
ls ~/.claude/state/*.log 2>/dev/null | while read f; do echo "$(tail -1 "$f")  <- $f"; done
```

Задача зарегистрирована, но её лог пуст или оборван месяц назад — она падает молча.

## Check 8 — Вики проектов: страницы правдивы, писатель жив?

Read-only.
- `__PYTHON__ ~/.claude/wiki-engine/wiki_lint.py --all` — любая ошибка → RED
  (lint в писателе не пропускает битое, значит страницу правили мимо писателя).
- `__PYTHON__ ~/.claude/wiki-engine/wiki_hook.py health` — непустой вывод → YELLOW.
- `stat -f %m ~/.claude/state/wiki/last_run` старше 24 ч → RED: писатель не запускается
  (`launchctl list | grep claude-wiki`, `~/.claude/state/local.claude-wiki.err`).
- Проекты claude-mem с наблюдениями за 14 дней, у которых нет `~/.claude/wiki/<имя>/router.md`
  и нет строки в `_exclude.txt` → YELLOW: обнаружение их пропускает.
- Размер: `router.md` тела > 40 строк или суммарно > 15 страниц — это ловит lint; здесь не дублировать.

## Отчёт

Записать в `~/.claude/audits/os-audit-YYYY-MM-DD.md` (сегодняшняя дата; если за сегодня файл уже
есть — добавить суффикс `b`, `c`, ...).

Структура:

1. **Шапка** — дата, область аудита, чем отличается от прошлого отчёта.
2. **Таблица статусов** — по одной строке на проверку, статус RED / YELLOW / GREEN и одна фраза
   сути. RED — приводит к неверным ответам уже сегодня; YELLOW — деградация; GREEN — в порядке.
3. **Что он ответит неправильно сегодня** — самая ценная часть. Не «freshness красный», а
   конкретно: «на вопрос про X даст уверенный ответ по состоянию на такую-то дату, и он будет
   неверен». Минимум три таких сценария, если находки позволяют.
4. **Fix-list на утверждение:**
   - **A — доделать начатое:** незавершённое, брошенное на середине
   - **B — роутинг и правда индексов:** битые ссылки, фантомы, сироты, счётчики
   - **C — догрузить данные:** устаревшие факты, требующие перепроверки
   - **D — устойчивость:** что сделать, чтобы та же проблема не вернулась
5. **Не проверено** — что не удалось и почему.

В чат вывести только таблицу статусов, сценарии неверных ответов и fix-list. Полный отчёт —
в файле, путь назвать.

## После отчёта

Спросить, что из fix-list выполнять. Не выполнять ничего без ответа. При согласии на пункт —
делать его как обычную задачу, с показом того, что меняется.
