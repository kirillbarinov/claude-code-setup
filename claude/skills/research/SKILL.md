# research — воронка v2

Принцип: **ответ строится из массы самостоятельно открытых источников, а не из синтеза поисковика по первым ссылкам.** Синтез Perplexity — обнаружение кандидатов; чистый синтез без открытых страниц не отдаётся ни в одном режиме.

## Шаг 1 — классифицируй вопрос (Стадия 0)

Класс определяется **типом доказательств, которые решают вопрос**, — не формой фразы. «Какой ноутбук взять для ML» звучит как ФАКТ, а решается как ВЫБОР.

| Класс | Признак | Решающее доказательство | Режим по умолчанию |
|---|---|---|---|
| **ФАКТ** | цена, лимит, версия, закон, синтаксис | первоисточник (офдок, changelog, текст закона) | quick / standard |
| **ПРАКТИКА** | «как правильно», выбор технологии | production-опыт, issues, бенчмарки | standard |
| **ВЫБОР** | «что купить», субъективное качество | масса отзывов долгосрочных владельцев + измерения | **wide** |
| **СОСТОЯНИЕ** | новости, релизы, «что сейчас» | первичный анонс + свежесть | quick / standard |

**Анонс обязателен** — одна строка до поиска: «Класс ВЫБОР → wide, ~20 мин» . Wide запускается автоматически по классу, но анонс даёт пользователю шанс прервать.

## Шаг 2 — проверь маршрут мимо поиска

- **API / синтаксис / конфиг библиотеки** → Context7 (`resolve-library-id` + `query-docs`); Perplexity только если пусто.
- **Известен конкретный URL** → `ezycopy <URL>` напрямую.
- **Длинный документ по URL** → `ctx_fetch_and_index` + `ctx_search`.
- **«Откуда взялся факт» / видео** → скиллы `source-finder` / `youtube-search`.
- **Прошлый факт из памяти (claude-mem)** — кандидат с датой источника, не готовый ответ: перепроверяется по классу.

## Шаг 3 — выбери режим по цене ошибки

| Режим | Когда | Потолок | Кто исполняет |
|---|---|---|---|
| **quick** | цена ошибки ≈ 0: название флага, дата релиза, любопытство | ~2–3 мин | инлайн, главный агент |
| **standard** | факт влияет на код, деньги или решение; ПРАКТИКА | 5–10 мин | субагент `researcher` |
| **wide** | ВЫБОР, сравнения, рынок, право с развилками | 15–25 мин | субагент `researcher`, ломатель всегда |

Сомневаешься — начни с quick и подними режим, если ответ упёрся в цифру, которая на что-то влияет. `researcher` вправе поднять класс/режим сам — с пометкой в отчёте; молча понижать нельзя.

## Шаг 4a — quick инлайн (Quick+)

1. 1–2 вызова `sonar` (`max_tokens=1500`, recency по свежести) **одним параллельным сообщением**.
2. **Обязательно открой 1–2 страницы первоисточника** из citations (`ezycopy`, проверка объёма >1–2 КБ). Чистый синтез не отдаётся никогда.
3. В ответе: утверждение + URL + дата источника (не сегодняшняя). Не открыл страницу — так и пиши: «по синтезу, первоисточник не открыт».

## Шаг 4b — standard / wide: спавни `researcher`

В промпте субагенту обязательно передай:
- **класс** и **режим**;
- сам вопрос + известный контекст (что уже известно, что решается этим ответом);
- **ставку** для standard: идёт ли факт в код/деньги/необратимое решение (включает ломатель, +~5 мин, с анонсом);
- что НЕ входит в задачу (при нескольких агентах — иначе перекроются).

**По умолчанию — один `researcher`**: он ведёт веер параллельно внутри себя. Несколько агентов — только под объективно независимые подвопросы (сравнение N сущностей → агент на сущность; юридическое отдельно от технического).

В промпте также задай **пути**: файл отчёта и папку сырья `<отчёт>-src/` (researcher обязан сохранить туда каждую открытую страницу — это вход ломателя).

Субагент вернёт отчёт: **Вывод / Обоснование / Кто не согласен / Не установлено / Покрытие** (+ прогон `validate-research-report.py` до 0 ошибок).

**Ломатель (wide — всегда; standard — при ставке):** после сдачи первичного отчёта спавнишь ВТОРОГО `researcher`-агента с задачей ОПРОВЕРГНУТЬ отчёт: передай путь к отчёту и src-папке; форма — «по ударам» (СТОИТ / ОСЛАБЛЕНО / ОПРОВЕРГНУТО + итог + скорректированный вывод); валидатор к breaker-отчёту не применяется. Поправка ломателя побеждает; оба не открыли первоисточник → факт в «Не установлено».

## Шаг 5 — отдай ответ

- Ответ пользователю — из отчёта, компактно, каждое ключевое утверждение с датой источника.
- «Не установлено» не прячется: пустой результат — результат.
- Cutoff — май 2026: всё после — искать обязательно, полгода до — проверять.

## Стадии воронки — конспект (детали исполнения — в определении агента `researcher`)

Держать здесь, потому что quick-режим идёт инлайн в главном агенте, где определения `researcher`'а нет.

**Иерархия доказательств инвертируется между классами.** Для ФАКТА сайт вендора — лучший источник. Для ВЫБОРА он же — маркетинг, худший; 30 независимых владельцев с одной жалобой через полгода использования — это измерение, а не мнение. Для ПРАКТИКИ офдоки отвечают «что умеет», но «что лучше» доказывается чужими шрамами: пост-мортемы, migration-посты, issues.

1. **Веер — один параллельный раунд.** Углы, не парафразы: прямой, опровергающий («problems», «deprecated»), альтернативный, негативный опыт («regret buying», «через год использования»), временной, языковой. **Правило родных языков:** 2–4 родных языка темы (страна вендора, крупнейшие сообщества, юрисдикция; en почти всегда), запрос на каждом. Два языка — скрытая форма «ответа по первым ссылкам». Каналы по классу: ФАКТ → офсайт / llms.txt / Context7; ПРАКТИКА → HN Algolia + GitHub search + инженерные блоги; ВЫБОР → Reddit через old.reddit + тест-лаборатории + форумы; СОСТОЯНИЕ → recency=day/week → первичный анонс.
2. **Отбор по разнообразию, не по рангу.** Тег стимула каждому источнику (`продаёт` / `аффилиат` / `медиа` / `практик` / `измеритель`); дедуп перепечаток (совпадающие формулировки без собственного измерения = один источник); квота ≥3 типов стимулов; **аффилиатный консенсус = ноль доказательств** — аффилиаты только генератор кандидатов.
3. **Батч-чтение.** Все страницы одним параллельным батчем, последовательное открытие запрещено. Проверка объёма (>1–2 КБ; 300 байт = cookie-баннер), кодировки, даты.
4. **Углубление.** Словарь инсайдера (термины темы, которых не было в вопросе) + **снежный ком** (источники, на которые ссылаются прочитанные) → 1 доп. раунд для standard, 2 для wide.
5. **Сводка.** Считается независимое согласие, не число упоминаний; несогласие фиксируется, не усредняется; квалификаторы цитируются вместе с цифрой до конца предложения; контрзапрос по решающему утверждению («<утверждение> wrong / myth / debunked»); **стоп по насыщению** — раунд без новых утверждений → отчёт, даже при неизрасходованном бюджете.

## Экономика

- Дефолт `model="sonar"`, `max_tokens=1500`; `sonar-pro` — только один вызов на синтез/citations, `max_tokens=1500–1800`, `temperature=0`; только сбор citations → `max_tokens=400`. Жёсткий потолок `max_tokens=2000`. `sonar-pro` дороже `sonar` в ~15×.
- `recency` (дефолт `month`): новости/цены/релизы → `day`/`week`; архив → `year`.
- Лимиты вызовов Perplexity: quick 2–3, standard 3–5, wide 5–8 — одним параллельным раундом (плюс раунды углубления).
- HN/GitHub API и открытие страниц денег не стоят — ширина за их счёт; но открытие входит в бюджет времени, поэтому только батчем.
- Сырой вывод поисковика в главный контекст не попадает никогда — обрабатывать и суммировать под вопрос.
- Персистентного кэша фактов нет, единственная память — claude-mem.
- Субагентов, спавнимых под research вне `researcher`, инструктировать в промпте: экономь веб-поиск, вывод короткий.
