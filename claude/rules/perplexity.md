# Поиск в интернете — алгоритм «Воронка» (v2)

## Принцип

Поисковик-синтезатор (Perplexity или любой другой) — инструмент **обнаружения**, а не ответа. Ответ никогда не равен синтезу поисковика: синтез — это и есть «первые ссылки, пропущенные через ИИ». Ответ строится из массы источников, открытых и разобранных самостоятельно. Единица работы — не «ответ поисковика», а **утверждение + независимые источники под ним**.

Пять стадий: **Классифицировать → Развернуть веер → Отобрать → Прочитать батчем → Свести**.

Канал: любой поиск идёт ТОЛЬКО через `mcp__perplexity-mcp__perplexity_search_web` (в главном контексте) плюс каналы внутри субагента `researcher`. Встроенный `WebSearch`/`WebFetch` не использовать; прямой `curl`/`wget` по публичному URL — тоже нет (guard режет). Не отвечать «из головы», если вопрос требует данных из интернета, — сначала искать.

## Стадия 0 — Классификация (главный агент, инлайн, без поиска)

Класс задаёт каналы, иерархию доказательств, бюджет и режим. Определяется **типом решающих доказательств, а не формой фразы**: «какую ORM взять» — по форме выбор, но решается production-опытом → ПРАКТИКА.

| Класс | Признак | Что доказывает | Бюджет |
|---|---|---|---|
| **ФАКТ** | цена, лимит, версия, закон, синтаксис API | первоисточник: офдок, текст закона, changelog, ответ API | 5 мин |
| **ПРАКТИКА** | «как правильно», best practices, выбор технологии | production-опыт, issue-трекеры, бенчмарки с методологией | 10 мин |
| **ВЫБОР** | «что купить», «что удобнее», субъективное качество | масса долгосрочных пользовательских отзывов + независимые измерения | 15–20 мин |
| **СОСТОЯНИЕ** | новости, релизы, «что сейчас» | первичный анонс/пресс-релиз + свежесть | 5 мин |

**Иерархия доказательств инвертируется между классами.** Для ФАКТА сайт вендора — лучший источник. Для ВЫБОРА он же — маркетинг, худший; а 30 независимых владельцев с одной и той же жалобой через полгода использования — измерение, а не мнение. Для ПРАКТИКИ офдоки отвечают «что умеет», но «что лучше» доказывается чужими шрамами: пост-мортемы, migration-посты, issues.

Классификация анонсируется одной строкой («класс ВЫБОР → режим wide, ~20 мин»); класс и режим передаются `researcher`'у в промпте. Researcher вправе поднять класс/режим с пометкой в отчёте; понижать молча нельзя.

## Режимы

Вторая ось — **ставка**: что сломается, если ответ неверен? Ничего → `quick`. Код/деньги/решение → `standard`. ВЫБОР, сравнение многих сущностей, дорогая покупка → `wide`.

- **quick** (~2–3 мин, инлайн): один раунд веера из 2–3 углов **плюс обязательное открытие 1–2 первоисточников** через `ezycopy` батчем. Чистый синтез без открытых страниц не отдаётся никогда. Факт из quick позже идёт в код/деньги/решение → обязательная перепроверка через standard.
- **standard** (5–10 мин, субагент `researcher`): полная воронка, 5–8 страниц. **Ломатель по ставке:** решающий факт идёт в код, деньги или необратимое решение → ломатель включается автоматически (+~5 мин, с анонсом); без ставки standard остаётся быстрым.
- **wide** (15–25 мин, субагент, для ВЫБОР/сравнений): запускается **автоматически по классу, с анонсом**, без блокирующего подтверждения — пользователь может прервать. 10–15 страниц, до двух раундов углубления; при сравнении N сущностей допустим агент на сущность с явным разделением зон. **Ломатель всегда:** после сводки второй агент получает отчёт с задачей его опровергнуть. Поправка ломателя побеждает; оба не открыли первоисточник → факт в «Не установлено».

Главный контекст не забивается: воронка живёт в субагенте (точка входа — скилл `research`), наружу выходит только сводка. По умолчанию — один `researcher`; несколько — только под объективно независимые подвопросы, каждому явно писать, что не его.

## Стадии воронки (исполняет `researcher`; детали — в его определении)

1. **Веер обнаружения — один параллельный раунд.** Запросы — разные углы, не парафразы: прямой, опровергающий («problems», «deprecated»), альтернативный, негативный опыт («regret buying», «через год использования»), временной, языковой. **Правило родных языков:** 2–4 родных языка темы (страна вендора, крупнейшие сообщества, юрисдикция; en почти всегда), на каждом — запрос на этом языке. Ограничение двумя языками — скрытая форма «ответа по первым ссылкам». Каналы по классу: ФАКТ → офсайт/llms.txt/Context7; ПРАКТИКА → HN Algolia + GitHub search + инженерные блоги; ВЫБОР → Reddit через `old.reddit.com` + тест-лаборатории + форумы; СОСТОЯНИЕ → recency=day/week → первичный анонс. Exa MCP (если установлен) — второй канал обнаружения.
2. **Отбор по разнообразию, не по рангу.** Тег стимула каждому источнику (`продаёт`/`аффилиат`/`медиа`/`практик`/`измеритель`); дедуп перепечаток (совпадающие формулировки без собственного измерения = один источник); квота ≥3 типов стимулов; **аффилиатный консенсус = ноль доказательств** — аффилиаты только генератор кандидатов.
3. **Батч-чтение.** Все страницы одним параллельным батчем; последовательное открытие запрещено. Проверка объёма (>1–2 КБ; 300 байт = cookie-баннер), кодировки, даты. JS-страница → Firecrawl MCP, если установлен.
4. **Углубление (3.5).** Словарь инсайдера (термины темы, которых не было в вопросе) + снежный ком (источники, на которые ссылаются прочитанные) → 1 доп. раунд (standard) / 2 (wide).
5. **Сводка — таблица утверждений.** Считается независимое согласие, не число упоминаний; несогласие фиксируется, не усредняется; квалификаторы цитируются вместе с цифрой до конца предложения; контрзапрос по решающему утверждению («<утверждение> wrong / myth / debunked»); **стоп по насыщению** — раунд без новых утверждений → отчёт, даже при неизрасходованном бюджете.

## Форма ответа

**Вывод / Обоснование / Кто не согласен / Не установлено / Покрытие.** Для ВЫБОРА вывод — ранжированный список с причинами. Каждое утверждение — с числом независимых источников, URL и **датой источника**, не сегодняшней. Не нашёл → «не найдено такими-то каналами», не правдоподобная заготовка. Отчёт researcher'а прогонять через `validate-research-report.py` — форма, бесплатно. Cutoff — май 2026: всё после искать обязательно, полгода до — проверять.

## Маршрутизация мимо поиска

| Тип | Куда |
|---|---|
| API, синтаксис, конфиг библиотеки | **Context7** (Perplexity только если пусто) |
| Известен конкретный URL | `ezycopy <URL>` напрямую |
| Длинный документ по URL | `ctx_fetch_and_index` + `ctx_search` |
| «Откуда взялся факт» / видео | скиллы `source-finder` / `youtube-search` |
| Прошлый факт из claude-mem | кандидат с датой источника, не ответ; для кода/денег/решений — перепроверка |

Персистентного кэша фактов нет — единственная память claude-mem.

## Экономика

- Дефолт `model="sonar"`, `max_tokens=1500`; `sonar-pro` — только один вызов на синтез/citations, `max_tokens=1500–1800`, `temperature=0`; только сбор citations → `max_tokens=400`. Жёсткий потолок `max_tokens=2000`. `sonar-pro` дороже `sonar` в ~15×.
- `recency` (дефолт `month`): новости/цены/релизы → `day`/`week`; архив → `year`.
- Лимиты вызовов Perplexity: quick 2–3, standard 3–5, wide 5–8 — одним параллельным раундом (плюс раунды углубления).
- HN/GitHub API и открытие страниц денег не стоят — ширина за их счёт; но открытие входит в бюджет времени, поэтому только батчем.
- Сырой вывод поисковика в главный контекст не попадает никогда — обрабатывать и суммировать под вопрос.
- Локальные хосты (localhost, 127.x, 10.x, 192.168.x, 172.16–31.x) `curl`'ом не блокируются.
- **Фолбэк при мёртвом Perplexity:** `touch ~/.claude/perplexity-guard.disabled` — 10-мин окно встроенного поиска; удалить флаг, когда ожил. Воронка не меняется — меняется канал обнаружения.
- Субагентов, спавнимых под research вне `researcher`, инструктировать в промпте: экономь веб-поиск, вывод короткий.

> Принуждение: hook `perplexity-guard.sh` (`PreToolUse` на `WebSearch|WebFetch` и `Bash`) блокирует встроенный веб-поиск и публичный `curl`/`wget` для главного агента, редиректит в Perplexity. Субагенты пропускаются по top-level полям `agent_id`/`agent_type` (именованный агент шлёт только `agent_type`; парсинг `jq`, не grep). Решения пишутся в `~/.claude/perplexity-guard.log`. Другие MCP (context-mode, Exa, Firecrawl) не покрываются.
