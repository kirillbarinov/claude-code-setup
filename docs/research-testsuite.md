# research-testsuite — регрессионный набор для конвейера доказательного поиска

Назначение: после любой правки в `agents/researcher.md`, `skills/research/SKILL.md` или
`hooks/perplexity-guard.sh` прогнать релевантные кейсы и сравнить с ожидаемым поведением.
Без этого файла каждая проверка строится заново и результаты несопоставимы.

**Как оценивать.** Эталон (ключ) строит главный агент, открывая первоисточник сам, ДО прогона.
Оценка по ключу, а не по правдоподобию отчёта. Где ключ невозможен (выбор технологии) —
оценка процессная: соблюдены ли обязательные шаги.

**Важно:** ключи протухают. У каждого кейса стоит `Ключ проверен:`. Если дата старше
полугода — перестроить ключ перед прогоном, иначе тест провалит верный отчёт
(ровно это случилось с УСН: витрина ФНС отстала, и мой ключ был неверен).

**Результат 2026-07-27:** конвейер 10/10 осей. Базовая линия 3/10, назвала Opus 4.8,

## T5 — вопрос без публичного ответа

**Что проверяем:** не выдумывает ли конвейер правдоподобное там, где данных нет.
**Как:** спросить величину, которую никто не раскрывал (доля продукта в выручке
непубличной компании и т. п.).
**Ожидаемо:** «Не установлено» с перечнем проверенных каналов; оценки третьих лиц —
максимум T2 с пометкой; никакой цифры в «Установлено».
**Провал:** любая конкретная цифра в «Установлено».
**Результат 2026-07-27: PASS, два независимых прогона.** Оба: в «Установлено» цифры нет;
≈18 % помечены как **наша арифметика из двух T0-чисел**, а не как раскрытие; посылка
вопроса («последний отчётный период») отвергнута — компания непубличная, отчётного периода
в этом смысле нет.
**Дефект инфраструктуры, найденный прогоном:** первый агент сообщил, что

Это дыра в спавне/определении агента, а не в методике. См. «Открытые дефекты».

## T6 — билингвальное расхождение

**Что проверяем:** правило «ru-контент по глобальным темам вторичен и устаревает».
**Утверждение:** «GitHub Free даёт 2000 минут Actions в месяц для приватных репозиториев
и 500 МБ хранилища Packages».
**Ключ:** `docs.github.com/en/billing/concepts/product-billing/github-actions`.
Открыт напрямую, `ezycopy`, 14 КБ. Ключ проверен: 2026-07-27.
- Free — 500 МБ artifact storage, **2 000** мин/мес, 10 ГБ кэша на репозиторий;
  Pro — 1 ГБ и **3 000** мин; Team — 2 ГБ и 3 000; Enterprise Cloud — 50 ГБ и 50 000.
- Публичные репозитории на стандартных раннерах и self-hosted — **бесплатно**, квота не тратится.
- 500 МБ — это **artifact storage**, и он **общий пул** с GitHub Packages, а не отдельные 500 МБ
  под Packages. Кэш (10 ГБ) в этот пул не входит.
- Минуты списываются с **владельца репозитория**, не с запустившего workflow.
**Главная ловушка (билингвальная):** ru-статьи повторяют старую модель множителей
«Windows ×2, macOS ×10». В актуальных доках множителей **нет** — есть явные поминутные
ставки по SKU: Linux 1-core $0.002, Linux 2-core $0.006, Linux arm64 $0.005,
Windows 2-core $0.010, macOS 3/4-core $0.062. Windows против Linux 2-core — это ×1,67,
а не ×2; macOS — ×10,3, а не ×10.
**Ожидаемо:** открыт en-первоисточник; поминутные ставки, а не множители; пул с Packages
разведён; бесплатность публичных репозиториев названа; расхождение с ru-источниками
зафиксировано явно, не усреднено.
**Провал:** ответ построен по ru-пересказу; «×2 / ×10» подано как действующее;
500 МБ названы отдельной квотой Packages.
**Результат 2026-07-27: PASS по всем осям и сверх ключа.** Агент нашёл во frontmatter
`redirect_from: /billing/reference/actions-minute-multipliers` — прямое доказательство, что
страницу множителей заменили поминутным прайсом; нашёл исходный reusable
`data/reusables/billing/actions-included-quotas.md` (коммит 2026-06-23); добавил лимиты
конкурентности; зафиксировал внутренний лаг самих доков (концептуальная страница
billing-and-usage всё ещё говорит «minute multipliers»). Вывод ×1,667/×10,333 честно
помечен как [T0-производное], а не как цитата.
**Повтор (`t6-bilingual-2`) не считается вторым испытанием конвейера:** он пришёл к тому же
вердикту целиком из кэша, который за минуты до этого записал первый агент. Честно об этом
сказал. Замер кэша, не поиска.

### T9-bis — перепрогон на некэшированном утверждении

**Утверждение:** «ISR Writes у Vercel стоят $4.00 за 1 млн Write Units — единая ставка
для всех регионов».
**Ключ построен вручную 2026-07-27**, открытием шести страниц
`vercel.com/docs/pricing/regional-pricing/<регион>` (по ~3,8 КБ каждая):
ISR Writes за 1 млн — iad1 **$4.00**, bom1 **$4.40**, syd1 **$5.20**, fra1 **$5.20**,
cpt1 **$5.60**, gru1 **$6.40**. ISR Reads ровно в 10 раз дешевле записи в каждом регионе
($0.40 / $0.44 / $0.52 / $0.52 / $0.56 / $0.64). Утверждение ложно: $4.00 — минимум
по регионам, а не единая ставка.
**Почему подходит:** ставки ISR в `research-log.md` отсутствуют (там лежит только
Fast Data Transfer), так что кэш кейс не закоротит; страница `docs/pricing` по-прежнему
прячет региональный разрез за JS-селектором.
**Дополнительная ловушка:** страница региона отсылает Active CPU и Provisioned Memory
на `docs/functions/usage-and-pricing` — то есть «региональная цена» размазана по двум
семействам страниц, и остановка на первом даёт неполный ответ.

**Результат 2026-07-27: PASS, канал отработал именно так, как задумано.**
Ключ совпал по всем шести регионам, которые я строил вручную, и агент **расширил его
до 20** ($4.00 в iad1/cle1/pdx1 … $6.40 в gru1, разброс 1,6×). Механика второго канала
подтверждена явно: grep по `research-log.md` — записи по ISR Writes нет; затем
`vercel.com/llms.txt` через `ezycopy -o` + `grep`, оттуда семейство из 20 статических
страниц, **которых не было в выдаче Perplexity**; сырой индекс в контекст не втянут.
Вызовов Perplexity — 2 (обнаружение + опровержение), цифры из синтеза не использованы.
**Сверх ключа — квалификатор, которого у меня не было:** 1 Write Unit = **8 КБ**
durable storage, запись в CDN-кэш бесплатна. Ровно тот класс условия, который синтез
теряет первым. Плюс замеченная закономерность: ISR Writes = 2 × Edge Requests того же
региона, сходится во всех 20 строках.
**Дисциплина границы соблюдена:** «включено 200 000 ISR writes/мес» встретилось в синтезе
и ушло в «Предположительно [T2]» с оговоркой, что `vercel.com/pricing` — JS-витрина
и она не открывалась. Витрина честно названа непокрытием, а не противоречием.
**Вывод по кейсу:** второй канал снимает именно **непокрытие**. Без него честный ответ был
бы «региональный разрез не установлен» — при существующих статических страницах с цифрами.
**Граница канала измерена, а не предположена.** Индекс есть у vercel (200 КБ), clickhouse
(100 КБ), platform.claude (58 КБ), neon (35 КБ), docs.github (29 КБ), cloudflare (16 КБ),
supabase (2 КБ). Нет ни в каком виде у yandex.cloud, nalog.gov.ru, cbr.ru, docs.astral.sh —
у всех четырёх и `llms.txt`, и `sitemap.xml` дают HTTP 404 (проверено `ezycopy`
и `ctx_fetch_and_index`), у cbr.ru в `robots.txt` строки `Sitemap:` нет. Поэтому правило —
один заход, промах не отрабатывать. Второй провал кейса: агент копает индекс на ru-домене.

## T10 — свежесть (`recency`)

**Что проверяем:** параметр `recency` в маршрутизации — новости и релизы требуют `day`/`week`,
иначе выдача притащит прошлогоднее и оно пройдёт как текущее.
**Как:** спросить состояние, изменившееся за последние дни (последний релиз быстро
движущегося проекта, курс, статус инцидента).
**Ожидаемо:** `recency="day"` или `"week"`; дата источника явно названа и свежая;
если свежего первоисточника нет — так и написано, а не подставлено последнее известное.
**Провал:** ответ по данным месячной давности без указания, что он мог устареть.
**Результат 2026-07-27: PASS, и выше ключа.** Вопрос — актуальный LTS Node.js и последний
релиз Current. Ответ: Active LTS — v24 «Krypton», последний патч **v24.18.0 от 2026-06-23**;
Current — **v26.5.0 от 2026-07-08**; v22 «Jod» с 2025-10-21 уже Maintenance, так что
ходовая формулировка «текущий LTS = 22» устарела.
- **`recency` осознан, а не проставлен по шаблону:** первый вызов (состояние релизов) —
  `week`, потому что месячное окно затянуло бы июньские сводки, где Current ещё 26.3/26.4;
  второй (опровержение, смена схемы релизов) — `month`, потому что анонс вышел раньше
  недели назад и недельное окно его бы отрезало. Оба `sonar`, `max_tokens=900`.
- **Дата свежести названа сильнее, чем требовал ключ.** Ключ просил дату страницы;
  агент судит по HTTP-заголовку `Date` ответа `nodejs.org/dist/index.json` (Mon, 27 Jul 2026
  19:04 GMT, запрос без кэша) — то есть по моменту чтения живого индекса релизов, а не по
  дате витрины. Плюс `Last-Modified` на `SHASUMS256.txt` и `published_at` в GitHub API.
- **Второй канал — машинный `dist/index.json` и `schedule.json` в репо `nodejs/Release`**,
  а не выдача Perplexity; `llms.txt` осознанно пропущен как менее точный для этой задачи.
  Perplexity использован только для обнаружения URL, ни одна цифра из синтеза не взята.
- **Главное по оси свежести:** агент нашёл блог-пост от 2026-07-21, анонсирующий
  security-релизы 26.x/24.x/22.x «on or shortly after Monday, July 27, 2026», и написал,
  что на момент проверки они ещё не опубликованы, а номера патчей могут смениться в течение
  суток. Это ровно то поведение, которое ключ и проверяет: не подставить последнее известное
  за текущее, а назвать срок годности ответа.
- **Расхождение обработано как разные события, а не как противоречие:** дата v22.23.1 —
  2026-06-22 в `dist/index.json` (дата сборки/тега) против 2026-06-23T16:44Z в GitHub
  Releases (момент публикации).
- **Опровержение дало содержательный улов:** с ветки 27.x Node переходит на одну мажорную
  версию в год, и каждая становится LTS после 6-месячной Current-фазы; v26 — последняя по
  чётно/нечётной схеме. Посылка «v26 не станет LTS» отклонена.

## T8 — хук perplexity-guard (без сети)

Прогоняется скриптом, детерминированно, стоит ноль:
| Вход | Ожидаемо |
|---|---|
| `WebSearch` без `agent_id` | deny |
| `WebFetch` без `agent_id` | deny |
| `WebSearch` с `agent_id` | allow (пусто) |
| `Bash: curl https://example.com` | deny |

| `Bash: curl http://192.168.1.5/x` | allow |

| `WebSearch` при свежем флаге `perplexity-guard.disabled` | allow (окно фолбэка) |
| `WebSearch` при флаге старше TTL=600 с | deny |

**Прогон:** `bash ~/.claude/hooks/perplexity-guard.test.sh` — 24 кейса, сети не трогает.

## T-time — потолок 5 минут

**Что проверяем:** главное требование к конвейеру — **ни один поиск не длится дольше
5 минут**, включая `deep`. Правило внесено 2026-07-27 после прогона, занявшего 16 минут.
**Как:** засечь `date` до спавна `researcher` и после получения отчёта. Брать кейс
заведомо тяжёлый: многоаспектный вопрос без канонической страницы (например «топ-5
чего-либо с обоснованием»), где соблазн открыть десяток источников максимален.
**Ожидаемо:**
- wall-clock ≤ 5 мин;
- запросы Perplexity ушли **одним сообщением, параллельно** (2–4 на verified, 4–6 на deep),
  запрос на опровержение — в том же раунде;
- страницы открыты **одним батчем** (`ezycopy ... & ... & wait` или `ctx_batch_execute`),
  а не по одной;
- если не всё успели — в «Покрытии» строка «бюджет 5 мин исчерпан, не добрал: …»,
  а недоведённые факты стоят на своём тире, а не выданы за проверенные.
**Провал:** превышение потолка; последовательные независимые запросы; молчаливое
превышение без строки в «Покрытии»; погоня за T0 по фактам, от которых ничего не зависит,
пока решающий факт остался непроверенным.
**Отдельно:** контрольный читатель в потолок **не влезает по построению** (идёт после
первого отчёта, удваивает время). Он выключен по умолчанию; если включён — потолок
считается как 2 × 5 мин и это должно быть заявлено пользователю заранее.
**Статус:** кейс заведён 2026-07-27, прогона ещё не было.

## T-stop — остановка на насыщении

**Что проверяем:** правило «останавливаться на насыщении, а не на исчерпании бюджета»
(внесено 2026-07-27). Лимит вызовов ловит только исчерпание; лишний раунд после
насыщения тратит время, которого не хватит на решающую страницу.
**Как:** взять вопрос с одним однозначным ответом на официальной странице, где второй
и третий угол поиска заведомо вернут те же домены (например текущая мажорная версия
библиотеки с активным релизным циклом). Считать раунды и вызовы по логу агента.
**Ожидаемо:**
- агент останавливается **раньше** лимита режима (`verified` 2–4 вызова) — как правило
  на одном раунде;
- в «Покрытии» названа причина остановки: ответ полон / сошлись 3 независимых
  источника / два раунда вернули одно и то же;
- невыбранный бюджет **не** отмечен как недоработка.
**Провал:** выбран полный лимит вызовов при том, что второй раунд не добавил ни одного
нового домена и ни одной новой цифры; «Покрытие» не называет причину остановки.
**Статус:** кейс заведён 2026-07-27, прогона ещё не было.

## Ключ оценки отчёта — пять осей

Любой прогон из набора оценивается по одним и тем же пяти осям. Оценка ставится по
каждой отдельно; средний балл не выводится — провал по любой оси делает прогон
неуспешным, потому что оси описывают разные классы отказа.

| Ось | Что смотрим | Провал |
|---|---|---|
| **Фактическая точность** | Совпадают ли числа, даты и условия с тем, что на странице | Верная цифра при потерянном квалификаторе — это провал, а не частичный успех |
| **Точность атрибуции** | Каждый факт ссылается на источник, где он действительно есть; тир соответствует природе источника | Ссылка «в общем по теме»; T2 подан как T0; занижение тира |
| **Полнота** | Все заявленные оси квалификаторов закрыты либо стоят в «Не установлено» | Молчаливо пропущенная ось — она же не отмечена как пропущенная |
| **Качество источников** | Для решающего факта — акт, а не витрина и не пересказ; для сравнения — независимое измерение, а не обзор | Вывод построен на T3; пять пересказов одного блог-поста зачтены как подтверждение |
| **Эффективность инструментов** | Раунды и вызовы против результата: параллельность, батч открытия, остановка на насыщении | Последовательные независимые запросы; полный лимит при нулевом приросте; открытые страницы, ни на что не повлиявшие |

Первые четыре оси оцениваются по отчёту, пятая — по логу прогона. Форму отчёта
(секции, тиры, URL, даты) отдельно оценивать не нужно: её детерминированно проверяет
`validate-research-report.py`, и это делается до содержательной оценки — непройденная
форма означает, что отчёт нельзя проверить и по существу.

## Базовая линия для сравнения

Наивный прогон = **один** вызов `mcp__perplexity-mcp__perplexity_search_web`,
`model="sonar"`, без открытия первоисточников. Ответ оценивается по тому же ключу,
что и конвейер. Смысл сравнения — не «конвейер лучше», а **какие именно классы ошибок**
он снимает: потерянный квалификатор, ложная посылка, устаревшая витрина, случайно
верная цифра.
