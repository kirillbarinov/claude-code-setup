# Авто-вики для всех проектов — дизайн

Дата: 2026-09-25 · Статус: утверждён в чате, ждёт ревью спека

## Цель

Когда данных станет много, ИИ должен находить нужное точно и дёшево: сначала короткий
маршрутизатор проекта, затем 1–5 страниц знаний, grep — только запасной путь. Вики ведётся
сама, без ручных просьб, для всех проектов сразу (пилот сознательно пропущен по решению
пользователя).

## Решения и их основания

| Решение | Основание |
|---|---|
| Маршрутизатор + страницы знаний, **без** пофайловой карты | Агентный поиск по коду лучше индекса (Anthropic отказались от RAG в Claude Code — mikeayles.com 2026-04-07, zenn.dev 2026-08-06); пофайловая карта протухает быстрее всего |
| В сессию автоматически грузится только маршрутизатор (≤40 строк) | ETH Zurich (arXiv 2602.11988, InfoQ 2026-03-06): LLM-сгенерированные context-файлы −3% успеха, +20% цены. Минимум в контексте, остальное по запросу |
| Каждая запись проходит детерминированный lint | Karpathy LLM Wiki (gist 2026-04-04): lint на противоречия, протухание, сирот |
| Порог протухания 60 дней, статусы active/archived | Хабр 1014868 (2026-03-25) |
| Централизованно в `~/.claude/wiki` | Проекты разбросаны по `~`, три — git-репо; один адрес для аудита и бэкапа. Офдок Anthropic large-codebases (2026-09-22) централизованное владение поддерживает |
| Знания — из claude-mem, не пересочинение кода | Наблюдения уже выжаты и привязаны к проекту и файлам |
| Отчёты исследования | `scratchpad/research/wiki-practice.md`, `wiki-breaker.md` сессии cea85047 |

## 1. Структура

```
~/.claude/wiki/                  git-репо, коммит на каждый прогон
  _index.md                      одна строка на проект: имя · путь · что это · дата
  _exclude.txt                   имена проектов, которые не вести (по строке)
  <Имя проекта>/                 имя = папка первого уровня в ~, как в claude-mem (UTF-8, пробелы допустимы)
    router.md                    ≤40 строк
    pages/<slug>.md              ≤150 строк каждая, ≤15 активных на проект
    archive/<slug>.md            протухшее; в сессию не грузится, в router не упоминается
```

**Определение проекта по cwd.** cwd внутри `$HOME` → первый компонент пути после `$HOME`.
Не проект: cwd == `$HOME`; первый компонент начинается с `.` (в т.ч. `~/.claude`); `Library`,
`Applications`, `Documents`, `Desktop`, `Downloads`; пути вне `$HOME` (`/private`, `/var`, `/tmp`);
имена из `_exclude.txt`.

**Frontmatter** (обязателен для `router.md` и страниц):

Лимиты строк считаются по телу файла, без frontmatter. Имя страницы — латиница kebab-case
(`pages/datchiki-tarirovka.md`).

```yaml
---
project: Лунная Станция
kind: router | page
summary: Платформа наблюдения за орбитой: датчики, телеметрия, отчёты   # только router, одна строка — идёт в _index.md
title: Датчики и тарировка        # для page
status: active | archived
updated: 2026-09-25               # дата последней правки
sources:                          # на чём основана страница
  - file: platform/api/src/.../Calibration.java
  - mem: 8030                     # id наблюдения claude-mem
---
```

**router.md — содержание:** путь к проекту; что это (1–2 строки); стек; точки входа; ключевые
папки с назначением; где тесты, конфиги, данные; команды запуска/сборки, если есть; список
страниц `pages/` с однострочным описанием. Ничего сверх этого.

**Страница знаний — одна тема:** решение и почему; устройство подсистемы; текущее состояние и
открытые вопросы; грабли проекта. История не копируется — ссылка на `mem:<id>`.

## 2. Чтение

**SessionStart-хук `wiki-session-start.sh`:** вычисляет проект по cwd. Если есть
`~/.claude/wiki/<проект>/router.md` — печатает его содержимое (без frontmatter) и строку-пометку,
если последний прогон проекта завершился ошибкой. Иначе молчит. Бюджет вывода ≤ 2600 символов (тело router ≤ 2000 символов держит lint; байты не
мерило — кириллица вдвое тяжелее); длиннее —
обрезается с пометкой.

**Правило в `~/.claude/CLAUDE.md`** (блок «Вики проектов», ≤6 строк):
1. Порядок: router (уже в контексте) → нужные `pages/` (не больше 5) → grep/glob.
2. Файл из `sources` новее `updated` страницы — верить файлу, не странице.
3. Вопрос про несколько проектов — начать с `~/.claude/wiki/_index.md`.
4. Вики не править руками в сессии — только через скилл `wiki`.

## 3. Запись

### 3.1 Очередь
**SessionEnd-хук `wiki-enqueue.sh`:** если `CLAUDE_WIKI_RUN=1` — выход. Иначе вычисляет проект
по cwd; если это проект — дописывает строку `<epoch>\t<проект>\t<cwd>` в
`~/.claude/state/wiki/queue.tsv`. Модель не вызывается. Время работы < 100 мс.

### 3.2 Писатель — `~/.claude/wiki-engine/wiki_update.py`
Запускается launchd `local.claude-wiki` каждые 2 часа (StartInterval 7200) и скиллом `wiki`.

1. **Замок:** `mkdir ~/.claude/state/wiki/lock` + pid внутри. Замок с мёртвым pid снимается.
   Не взял — выход 0.
2. **Очередь:** атомарно забрать `queue.tsv` (rename), дедуп по проекту. Плюс проекты без
   `router.md` (первичная сборка) — **не более 3 первичных сборок за прогон**.
3. **Дельта проекта** (с `last_ok_epoch` из `~/.claude/state/wiki/projects.json`; для первичной
   сборки — вся история):
   - claude-mem, read-only (`file:…claude-mem.db?mode=ro`): `observations` (id, type, title,
     facts, files_modified, created_at) и `session_summaries` (request, learned, completed,
     next_steps) где `project` = имя, после отсечки; не более 200 наблюдений + 50 сводок,
     свежие первыми;
   - файлы: git-репо → `git log --name-status --since`; иначе → файлы с mtime > отсечки,
     без `node_modules`, `.git`, `.venv`, `venv`, `__pycache__`, `build`, `dist`, `.next`,
     `target`; не более 300 путей;
   - дерево верхних двух уровней проекта (для router).
4. **Staging:** копия `~/.claude/wiki/<проект>/` в `~/Library/Caches/claude-wiki/staging/<проект>/` —
   вне `~/.claude`: Claude Code в `-p` молча запрещает запись в любые `.claude/` (проверено 2026-09-25).
5. **Вызов модели** — cwd = staging-папка:
   ```
   CLAUDE_WIKI_RUN=1 claude -p \
     --restricted --strict-mcp-config --no-session-persistence \
     --model opus --effort <medium|low> --fallback-model sonnet \
     --settings '{"permissions":{"deny":["Edit(/<корень проекта>/**)"]}}' \
     --allowedTools "Read Glob Grep Write Edit" \
     --append-system-prompt-file ~/.claude/wiki-engine/prompt.md \
     --add-dir "<корень проекта>" \
     < delta.md
   ```
   Промпт — только через stdin: `--add-dir` жадный и съедает позиционный аргумент.
   Запрет пишется как `Edit(//abs/path/**)` — правило `Edit` покрывает и Write; правило `Write(...)`
   файловыми проверками не матчится.
   Прогон без изменений (0 наблюдений, 0 изменённых файлов, нет битых источников) модель не
   вызывает — только отмечает успех.
   `--effort medium` — первичная сборка и правка страниц; `--effort low` — прогон, где дельта
   затрагивает только структуру (новые/удалённые папки верхнего уровня) без новых наблюдений.
   Таймаут 15 мин на проект.
6. **Lint** (`wiki_lint.py`, без модели) по staging. Провал → staging удаляется, ошибка в
   `projects.json` (`last_error`, `last_error_epoch`), проект возвращается в очередь не более
   2 раз подряд, дальше ждёт следующего изменения.
7. **Успех:** staging заменяет `~/.claude/wiki/<проект>/`; обновляется строка проекта в
   `_index.md`; `git add -A && git commit -m "wiki: <проект> (<N> стр.)"`; `last_ok_epoch`.
8. **Архивация (в том же прогоне, детерминированно):** страница со `status: active`, у которой
   `updated` старше 60 дней **и** все `file`-источники исчезли → переносится в `archive/`,
   `status: archived`, строка удаляется из router.

### 3.3 Промпт модели (`prompt.md`) — обязательные пункты
- Пиши только в текущую папку; формат и лимиты из §1; frontmatter обязателен.
- Обновляй существующие страницы, а не плоди новые; новая страница — только новая тема.
- Каждое утверждение опирается на источник из дельты или на прочитанный файл проекта; нет
  источника — не пиши.
- Противоречие старой странице с новыми данными — исправь страницу, старое не сохраняй.
- router: только маршрутизация, без знаний.
- Язык страниц — русский; идентификаторы и пути — как есть.

### 3.4 Lint — правила
Нарушение любого → провал:
- frontmatter есть и валиден; `project` совпадает с папкой; `kind` корректен; `updated` —
  дата `YYYY-MM-DD`; `sources` непуст; у router есть `summary`;
- в `pages/` только `status: active`, в `archive/` только `archived`; имя — `[a-z0-9-]+\.md`;
- тело `router.md` ≤ 40 строк, страницы ≤ 150 строк, активных страниц ≤ 15;
- каждый `file:` источник router и `pages/` существует относительно корня проекта (у `archive/`
  не проверяется — они там именно потому, что источники исчезли); каждый `mem:` существует в БД;
- каждая страница в `pages/` упомянута в router (нет сирот); каждая ссылка router → страница
  существует;
- в staging нет файлов вне `router.md`, `pages/*.md`, `archive/*.md`.

### 3.5 Скилл `wiki`
`~/.claude/skills/wiki/SKILL.md`. Триггеры: «обнови вики», «обнови вики <проект>»,
«пересобери вики <проект>», «что в вики». Действия: поставить проект(ы) в очередь и запустить
`wiki_update.py` в фоне; «пересобери» — удалить `last_ok_epoch` проекта (первичная сборка);
«что в вики» — показать `_index.md`.

## 4. Сохранность и надзор

- **git** в `~/.claude/wiki`, коммит на каждый успешный проект. Откат — `git revert`.
- **Бэкап:** launchd `local.claude-wiki-backup` ежедневно 12:51 → `tar.gz` в
  `~/Yandex.Disk.localized/claude-wiki-backup/` (или `CLAUDE_WIKI_BACKUP_DIR`), ротация 7.
- **os-audit:** новая проверка «Вики» — lint всех проектов, очередь старше 24 ч, последний
  успешный прогон старше 24 ч при непустой очереди, проекты с `last_error`.
- **os-audit-staleness.sh:** строка при старте сессии, если у любого проекта `last_error` новее
  последнего успеха или писатель не отрабатывал больше 24 ч.
- **CLAUDE.md:** строки в «Карту расположения» (wiki, wiki-engine, state/wiki) и в таблицу
  расписания (`claude-wiki`, `claude-wiki-backup`).

## 5. Граница с claude-mem
Вики — что верно сейчас; claude-mem — история. Вики ссылается на `mem:<id>`, не копирует.
Прогоны писателя не должны попадать в claude-mem (проверяется при реализации, см. §7).

## 6. Вне объёма
Пофайловая карта; эмбеддинги/RAG; вики для самого `~/.claude`; ручное редактирование страниц;
синхронизация на другие машины; пилот и A/B-замер пользы (сознательно пропущены).

## 7. Проверки при реализации (блокирующие)
1. ✅ 2026-09-25 спайк: `claude -p --restricted …` работает по подписке (OAuth). `--bare`
   запрещён — игнорирует OAuth.
2. ✅ 2026-09-25 спайк: прогон `--restricted` не создал сессии в claude-mem (`sdk_sessions`
   без новых строк через 30 с).
3. ✅ 2026-09-25 спайк: запись вне рабочих папок заблокирована; запись в `--add-dir`-проект
   заблокирована правилом `Edit(//…/**)`, чтение разрешено.
4. Lint отлавливает каждое правило §3.4 (по одному негативному примеру на правило).
5. Первичная сборка одного проекта end-to-end: router ≤40 строк тела, lint зелёный, коммит,
   хук SessionStart печатает router.
6. Писатель, запущенный из launchd (`launchctl kickstart`), проходит OAuth — окружение launchd
   беднее интерактивного.

## 8. Стыковка с существующими системами

Обнаружено при планировании (обе системы построены 2026-09-16 и не были в карте расположения):

**project-memory** (`hooks/project-memory-start.sh`, `hooks/project-memory-stop.sh`) — дневник
`<проект>/.claude/STATE.md`, целиком в контекст на старте, обновление по Stop-хуку. Покрывает
4 проекта; у Лунной Станции 805 строк в каждой сессии. **Вики его заменяет:**
- при первичной сборке все `.claude/STATE.md` проекта (глубина ≤3) идут в дельту как главный
  источник знаний (не более 1000 строк на файл);
- регистрация обоих хуков удаляется из `settings.json`; скрипты переносятся в
  `~/.claude/backups/retired-2026-09-25/`; файлы `STATE.md` в проектах не трогаются (архив).

**project-map** (`hooks/project-map-build.mjs`, `hooks/project-map-start.sh`) — детерминированная
карта папки в блоках `КАРТА:НАЧАЛО/КОНЕЦ` внутри `CLAUDE.md` значимых папок кодовых проектов,
подгружается Claude Code по требованию. **Остаётся без изменений.** Дельта перечисляет
`CLAUDE.md` с этими блоками; router ссылается на них вместо того, чтобы описывать папки заново.

Обе системы вносятся в «Карту расположения» `CLAUDE.md`.

**Обнаружение проектов для первичной сборки:** имена из колонки `project` таблицы
`observations` claude-mem, для которых `~/<имя>` — папка и `project_for` признаёт её проектом.
Проект, трижды подряд проваливший первичную сборку, из обнаружения выпадает до следующей
постановки в очередь хуком.
