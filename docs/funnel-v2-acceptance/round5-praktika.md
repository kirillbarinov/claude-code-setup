# Стоит ли в 2026 переводить прод-монорепо (TS, ~200k LOC, ESLint+Prettier, кастомные ESLint-плагины) на Biome?

Класс: ПРАКТИКА. Режим: standard со ставкой. Старт 02:00, финиш 02:10 (мск-таймзона хоста).
Проверяемая версия Biome на дату отчёта: `@biomejs/biome@2.5.6`, опубликован 2026-07-28 (GitHub Releases API, `repos/biomejs/biome/releases`).

## Вывод

**Полная миграция (снести ESLint) — нет. Частичная — да, и только в такой очерёдности:**

1. **Prettier → Biome formatter (низкий риск, наибольшая отдача).** Форматтер — то, где вендорская цифра ускорения хотя бы имеет измеренную ось, а совместимость заявлена: «scores **97% compatibility with _Prettier_**» (biomejs.dev, страница открыта 2026-07-30). Риск: один большой diff-коммит + расхождения на embedded-языках (см. «Кто не согласен»).
2. **Biome как второй линтер поверх «дешёвых» правил, ESLint остаётся ради кастомных плагинов.** Это то, что делают все найденные практики, включая тех, кто мигрировал успешно.
3. **Полный отказ от ESLint на Biome — только если ваши кастомные плагины сводятся к «запретить паттерн»**, потому что Biome не умеет запускать ESLint-плагины вообще: кастомные правила существуют исключительно как GritQL-сниппеты. Дословно (вендорский блог анонса v2, 2025-06-17): «Biome 2.0 comes with our first iteration of Linter Plugins. **These plugins are still limited in scope: They only allow you to match code snippets and report diagnostics on them.**» JS-плагины (ESLint-подобный API) в Biome **не выпущены** — PR `feat(js_plugin): runtime AST bindings for JS plugins` (#10954) открыт, обновлён 2026-07-19; зонтичный issue #2469 «JavaScript plugin runtime» открыт с 2024-04-15.
4. **Если цель именно «убить ESLint, сохранив кастомные плагины» — кандидат не Biome, а Oxlint.** У Oxlint есть ESLint-совместимый JS-plugin API, но с квалификатором из его же доки (oxc.rs, открыто 2026-07-30): «**JS plugins are currently in alpha, and remain under active development.**»

Что это значит для вашего профиля (200k LOC, монорепо, кастомные плагины): выигрыш по времени реален, но он приходит **от вытеснения ESLint/Prettier, а не от «Biome быстрее»**, и ровно ваши кастомные плагины — та часть, которую Biome сегодня не забирает. Реалистичный итог миграции — двухинструментальный пайплайн (Biome + урезанный ESLint) плюс сохранённый `tsc --noEmit`.

## Обоснование

- **Кастомные ESLint-плагины на Biome не переносятся — только переписываются в GritQL, и это pattern-matching, а не rule API.** [3 незав.] Дока плагинов: «Biome Linter supports GritQL plugins. Plugins can match specific code patterns, report customized diagnostics, and suggest fixable rewrites» (https://biomejs.dev/linter/plugins/, страница без даты, снята 2026-07-30) — верхний тир; блог v2 (https://biomejs.dev/blog/biome-v2/, 2025-06-17) даёт дословный квалификатор «still limited in scope»; практик: «migrating an entire company style guide from ESLint to Biome was nearly impossible because it relied on many rules from other ESLint plugins. Writing these rules / plugins ourselves was too much effort» (HN, exiguus, 2025-05-07, https://news.ycombinator.com/item?id=43920803).
- **Roadmap 2026 не обещает JS-плагины.** [1 незав.] В https://biomejs.dev/blog/roadmap-2026/ (2026-01-21) grep по «JS plugin»/«JavaScript plugin» даёт 0 совпадений; про плагины сказано только про GritQL: «Added support for plugins via GritQL … allowing users to **query the Biome CST** and report custom diagnostics». Планы 2026 — embedded-языки, HTML/Vue/Svelte/Astro, cross-language rules, opt-in `workspaces`, SCSS, LSP. То есть ставка «дождёмся ESLint-совместимых плагинов в 2026» первоисточником не подкреплена.
- **Type-aware правила Biome существуют, но нестабильны и заведомо неполны.** [3 незав.] Дословно: «Preliminary testing shows that our `noFloatingPromises` rule, which is based on our new type inference work, can detect floating promises in about **75% of the cases** that would be detected by using `typescript-eslint`, at a fraction of the performance impact» (blog v2, 2025-06-17) — ось: одно правило, «preliminary testing», против typescript-eslint. (б) Дока правила сегодня: категория `lint/nursery/noFloatingPromises`, дословно «This rule belongs to the nursery group, which means it is **not yet stable and may change in the future**» (https://biomejs.dev/linter/rules/no-floating-promises/, снято 2026-07-30) — то есть спустя год после v2 правило всё ещё nursery. (в) Независимый тест: uhyo проверил вывод типов на 2.0.4 и показал, что Biome не выводит тип возврата из тела функции («it seems that Biome cannot perform this kind of type inference», «to utilize Biome's type inference, it is important to explicitly state the return type of functions») и падает на дженериках (https://dev.to/herrington_darkholme/trying-out-biome-v2s-type-inference-and-knowing-its-limits-1j36 — англ. перевод статьи uhyo с Zenn, версия 2.0.4; это ОДИН источник, а не два, несмотря на два URL).
- **Type-aware движок активно чинится прямо сейчас — признак незрелости, а не готовности.** [1 незав.] Changelog 2.5.4→2.5.6 (https://biomejs.dev/internals/changelog/version/2-5-4...latest/, версии от 2026-07-15…2026-07-28): «Biome no longer panics when a type-aware rule such as `noFloatingPromises` checks a call to a function with multiple call signatures imported from another module» (#10963), «Fixed a performance regression in `noMisusedPromises` that caused type inference to run repeatedly while linting a file» (#11035), «Fixed a performance regression in type-aware JavaScript lint rules by inferring only requested types and memoizing export resolution» (#11009). Трекер: серия stack-overflow на darwin-arm64 с type-aware nursery-правилами — #10411, #10492 (закрыты), #10760 **открыт**, обновлён 2026-06-26.
- **Biome не заменяет `tsc`, по заявлению самих мейнтейнеров.** [1 незав.] Зонтичный issue «Type-aware linter» https://github.com/biomejs/biome/issues/3187 (закрыт 2025-06-13): «Note that we are **not trying to implement a full-fledged type system or a type checker like TypeScript**». Плюс RFC мульти-файлового анализа https://github.com/biomejs/biome/discussions/4653 (2024-11, снят 2026-07-30): «In general I think it is fair to say that Biome *will* become slower, simply because it will have more work to do».
- **Вендорская цифра скорости — про форматтер против Prettier, не про линт против ESLint.** [1 незав.] (ось зафиксирована) Дословно с https://biomejs.dev/ (Firecrawl, страница снята 2026-07-30, версия 2.5.6 от 2026-07-28): «~35x … Faster than Prettier when formatting **171,127 lines of code in 2,104 files with an Intel Core i7**». Ни ESLint, ни type-aware правила, ни cold/warm в этой оси не участвуют.
- **Независимое измерение: «Biome быстрее» — не источник выигрыша; выигрыш даёт удаление ESLint.** [1 незав.] Nicolas Charpentier, 2026-05-13 (https://charpeni.com/blog/migrating-from-eslint-biome-prettier-to-oxlint-oxfmt): «**Full lint pipeline (Biome + ESLint → Oxlint + Oxfmt):** ~81s → ~2.5s»; при этом «**Lint only (Biome native rules → Oxlint native rules):** ~3s → ~0.7s», «Format only (Biome → Oxfmt): ~2.9s → ~1.9s», «A project that was already on Biome went from ~500ms to ~500ms (parity)». И объяснение оси: «The headline number (81s → 2.5s) comes from **eliminating ESLint entirely**. Most of that 81 seconds was ESLint resolving imports for a custom architectural rule (`import/no-restricted-paths`)». Приведены все строки его таблицы, не только удобная.
- **Монорепо в Biome v2 поддержано, но по DX сами мейнтейнеры называют текущую реализацию ошибкой.** [2 незав.] Дока: «Since v2, Biome supports monorepos out of the box… nested configuration files must have the field `"root"` set to `false`», микросинтаксис `"extends": "//"` (https://biomejs.dev/guides/big-projects/, снято 2026-07-30). Roadmap 2026 (2026-01-21) в разделе про monorepo-out-of-the-box говорит про «poor DX introduced by monorepo-out-the-box» и предлагает opt-in `workspaces`, с квалификатором «**this is mostly an idea**» и общей оговоркой статьи «We can't promise that all of these features will be implemented».
- **Правил у Biome сейчас много (порядок — сотни), включая порты плагинных наборов.** [1 незав.] На https://biomejs.dev/linter/javascript/rules/ (снято 2026-07-30) 644 ссылки вида `/linter/rules/` — это верхняя оценка числа JS/TS-правил с повторами по группам; в списке присутствуют порты playwright/vue/svelte/react-native/drizzle-правил. Точное число правил утверждаю только порядком: несколько сотен. Группы в выгрузке ezycopy потеряны, поэтому распределение recommended/nursery по этой странице не считаю.

## Кто не согласен

- **«Миграция прошла отлично, ESLint почти не нужен».** insin (HN, 2025-05-07, https://news.ycombinator.com/item?id=43917235): выигрыш был в том, что не надо тащить дерево ESLint-зависимостей («the 1,000 line haircut to package-lock.json was appreciated»), «Migrating was just switch the dependencies and keep adding rules… **but we didn't go that mad with the ESLint config prior to that**» — то есть квалификатор прямо противоположен вашему кейсу (кастомные плагины). Он же жалуется на VS Code-расширение: «not picking up config files… needing restarted sometimes».
- **Форматтер: возврат к Prettier из-за embedded-языков.** sibeliuss (HN, 2025-05-07, https://news.ycombinator.com/item?id=43918165): «the current formatter (afaik) doesn't support embedded languages properly, so something like `const foo = graphql\`…\`` wont get formatted. In a big graphql codebase… its totally essential». Roadmap 2026 подтверждает, что это всё ещё пункт плана («JavaScript embedded languages: improve the DX of the embedded languages in JavaScript, such as CSS and GraphQL»).
- **Полный откат на ESLint из-за JSX/TSX-плагинов.** exiguus (HN, 2025-05-07): «as soon as JSX/TSX with React or Angular came into play, we encountered lagging issues with popular plugins and configurations. The number of bugs increased, prompting us to revert to ESLint».
- **Reddit 2025: причина отката — кастомизация.** Автор треда, 2025-02 (https://old.reddit.com/r/webdev/comments/1in18wd/switched_from_biomejs_to_eslint_whats_your_take/, «submitted 1 year ago»): «I tried Biomejs for a while, but I switched back to ESLint because I needed more customization options»; комментатор wadamek65: «I probably wouldn't use Biome in larger scale projects due to a lack of a plugin system». Квалификатор: тред годовалый, до v2 и GritQL — как «состояние сегодня» не годится, годится как история.
- **Оптимистичный «3 месяца в проде» отчёт — отклонён как ненадёжный.** https://codeclash.dev/blog/biome-production-3-months-retrospective/ (даты публикации на странице нет) утверждает «That was true for Biome 2.0. **Biome 2.4 shipped with GritQL**» — это противоречит первоисточнику: блог v2 (2025-06-17) прямо пишет «Biome **2.0** comes with our first iteration of Linter Plugins». Источник с проверяемой ошибкой в версионировании я не считаю в независимые; его цифры (847 файлов, 31s→2.3s) в обоснование не берутся.
- **Кейс «27.2s → 1.8s» — стимул `продаёт`.** https://fireup.pro/news/pre-commit-hooks-15x-faster-biome-vs-eslint-case-study — блог агентства о своей же команде, без методологии; ось при этом честно указана и она гибридная: «Biome handles 90% of formatting and linting tasks, while a **minimal ESLint configuration is retained** for rules Biome does not yet support», «Pre-commit hooks 24–30s → ~1.8–8s». Как доказательство «за» не считается, как иллюстрация гибридного паттерна — да. Grep обеих страниц (codeclash/fireup) на общие формулировки («shadow mode») дал 0 — это не перепечатки друг друга, но и не независимые измерения одного и того же.

## Не установлено

- **Точное число «сколько из ваших кастомных правил выразимо в GritQL»** — не устанавливается извне; единственный найденный способ измерения — прогнать `biome migrate eslint --write` и посмотреть, что не смапилось (совет фигурирует в вендорской доке миграции и в отклонённом codeclash; независимой методики не нашёл).
- **Свежие (2026) публичные отчёты о миграции монорепо ≥100k LOC именно на Biome с числами** — не найдено каналами: Perplexity (7 запросов, en/ja/ru), Exa (3 запроса), HN Algolia (4 запроса, включая поиск по комментариям), GitHub search. Практически всё, что находится в 2026 году в топе — недатированные SEO/AI-страницы (toolchew.com, pkgpulse.com, nerdleveltech.com, pockit.tools, abrarqasim.com, codeclash.dev), и единственный датированный практик-отчёт по монорепо (charpeni, 2026-05-13) — про уход с Biome+ESLint на Oxlint.
- **Актуальность issue #7332 «Type-aware rules fail to work»**: `state=open`, создан 2025-08-26, последнее обновление 2025-11-05 на Biome 2.2.0 — активности >6 мес., репро на устаревшей версии, поэтому в обоснование не поставлен.
- **Состояние линтинга шаблонов Vue/Svelte «сегодня»** — точно не установлено. Есть только косвенное: roadmap 2026 ставит целью «Enhance existing lint rules so that they work for HTML-ish languages too, notably Vue, Svelte, and Astro» и открытый tracking issue #10540 «port eslint-plugin-svelte rules» (обновлён 2026-06-02). Прямого утверждения вендора «шаблоны не линтуются» я на доках не нашёл, а вторичка (codeclash) дискредитирована.
- **Комментарии двух Reddit-тредов про v2** (`r/javascript/1led1rl`, `r/typescript/1ldwrxr`) — не прочитаны: ezycopy отдал 475 байт (только тело поста, дважды — первая попытка и повтор), Firecrawl v2 вернул пустой `data.markdown` (5 байт «FAIL») по обоим URL. Третья ступень — «не установлено».
