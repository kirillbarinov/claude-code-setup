# Моушн-слой: режим, сигнатурный момент, спека

Читается директором в §2 и §3. Числа здесь нормативные: любая длительность в коде обязана быть одним из токенов, проба «движение» `qa.mjs --design=DESIGN.md` это проверяет.

## 1. Режим — из четырёх строк задачи страницы (§1а), не из вкуса

| Режим | Признак по §1а | Разрешено | Запрещено |
|---|---|---|---|
| `кино` | задача страницы — убедить или впечатлить: лендинг, промо, портфолио, кейс | вход героя с хореографией; одно скролл-поведение; фоновое медиа | второе скролл-поведение; reveal на каждую секцию |
| `продукт` | задача — найти, сравнить, ввести, сделать: каталог, форма, дашборд, карточка | вход первого экрана — в пределах токена `enter` (300–600 мс), одним движением; одно подписное микровзаимодействие | скролл-кино; стаггер по карточкам; токен `scene` |

Неоднозначно по §1а — вопрос заказчику в интервью §1в, вместе с остальными. Режим записывается в DESIGN.md (`motion.mode`).

## 2. Сигнатурный момент — ровно один на страницу

Три строки в DESIGN.md: **где** (селектор или секция), **что происходит** (одна фраза без прилагательных), **чем доказывается** (какие кадры контакт-листа `motion.mjs` его показывают).

- `кино`: вход героя (стаггер слов / blur-in / раскрытие маской) **плюс** одно из: пин со скрабом, липкое медиа с затуханием, параллакс слоёв, скролл-раскрытие текста.
- `продукт`: одно микровзаимодействие, отличающее продукт: переход состояния («нет в наличии», «отправлено»), раскрывашка с данными, живой фильтр.

Всё остальное — тишина: переходы состояний по токену `micro`, без входных анимаций на секции. «Всё появляется одним fade» и «reveal на каждую секцию» — один и тот же дефект.

## 3. Блок `motion:` во фронтматтере DESIGN.md

```yaml
motion:
  mode: кино            # кино | продукт
  stack: css            # css | css+gsap-lenis | framer-motion
  tokens:
    micro: 150ms        # 120–180: наведение, фокус, переключатели
    enter: 450ms        # 300–600: вход элемента
    scene: 1000ms       # 800–1200: хореография героя целиком; только кино
  easing:
    out: cubic-bezier(0.22, 1, 0.36, 1)     # вход
    inout: cubic-bezier(0.65, 0, 0.35, 1)   # перемещение; linear — только скраб по скроллу
  stagger: 60ms         # 40–90
  distance: 24px        # 12–40
  properties: [transform, opacity, filter]
  reduced_motion: конечный кадр мгновенно
  signature:
    where: .hero
    what: слова заголовка входят снизу с blur-in, медиа липнет и гаснет к концу секции
    proof: motion-1440-hero кадры 2–8, motion-1440-scroll кадры 3–10
```

Правила: `properties` — закрытый список, layout-свойства (`width`, `height`, `top`, `left`, `margin`, `padding`) не анимируются; `reduced_motion` означает «показать итог сразу», а не «спрятать»: `.reveal{opacity:0}` без `no-js`/reduce-страховки — дефект; в режиме `продукт` токена `scene` нет.

## 4. Стек — по проекту

| Проект | Стек | Библиотека |
|---|---|---|
| статический HTML/CSS | `transition`, `@keyframes`, `animation-timeline: scroll()/view()` под `CSS.supports` | GSAP + ScrollTrigger + Lenis только если момент — пин или скраб |
| React / Next | Framer Motion (`motion/react`): `variants`, `staggerChildren`, `useScroll`/`useTransform` | Lenis допустим; GSAP и Framer на одном элементе не смешивать |

API библиотеки — через Context7 перед первой строкой кода; версия фиксируется в проекте.

## 5. Как это проверяется

`motion.mjs` пишет вход героя и скролл-проход на 1440 и 390 (§6г директора), критик ставит ось Motion по контакт-листу, гейт §6б держит порог: `продукт` ≥ 3, `кино` ≥ 4. Проба «движение» ловит длительности вне токенов, layout-свойства, reveal без страховки, `scene` в режиме `продукт` (в режиме `кино` длительности, равные токену `scene` ±10 мс, «долгими» не считаются).

**`--act "<селектор>"`** (опционально) — снимает окно после клика по узлу: клик, затем ещё `--hero` мс записи, контакт-лист `<name>-motion-<W>-act.png`, JSON получает `act: {selector, frames}` (или `act: null`, если флаг не передан). Нужен для доказательства сигнатурного момента режима `продукт` — там момент отвечает на действие, а не на загрузку. Селектор не найден на странице → `MOTION_FAIL: act selector not found`.

**`--force`** — разрешить перезапись файлов раунда (`-hero/-scroll/-act.png`, `.json`) с тем же `--name`; без него инструмент отказывается с `MOTION_FAIL`, чтобы акт-прогон не затёр раскадровки. **`--debug`** — отметки времени по шагам в stderr; весь запуск ограничен сторожем `3×hero + scroll + 60 с`, зависший шаг даёт `MOTION_FAIL`, а не вечное ожидание. На время съёмки и прогрева инструмент сам глушит `scroll-behavior: smooth`.

**reduced-motion:** PSNR ≥ 30 dB между кадром reduced и конечным кадром входа — порог совпадения `reducedMatch`.
