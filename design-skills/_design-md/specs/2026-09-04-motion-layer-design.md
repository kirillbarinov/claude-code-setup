# Спека: моушн-слой и ужатие протокола `design-director`

Дата: 2026-09-04. Статус: на проверке у заказчика.

## 1. Зачем

`design-director` (1107 строк) — машина «не быть плохим»: 41 проба `qa.mjs`, слепой критик, LEARNED.md, стоп-критерий «ни одна ось < 3». Ничто в цикле не требует хотя бы одного спроектированного момента на странице, а моушн не проверяется вовсе: съёмка идёт с `reducedMotion: 'reduce'`, критик видит только статику. Промпт на 60 % состоит из справочного балласта и содержит прямые противоречия, поэтому исполняется выборочно.

Источник вдохновения — публичные уроки motionsites.ai (https://motionsites.ai/lesson/build-animated-website-with-ai, https://motionsites.ai/lesson/build-animated-website-with-motionsites). Берём принципы, не промпты:

1. единица работы — секция с сигнатурным моментом, продаёт первый экран;
2. промпт — спецификация с числами (px, rgba, blur, кривые, шаг стаггера), а не бриф;
3. ограниченный повторяемый словарь эффектов;
4. доказательство результата — движущаяся картинка, не статичный кадр.

## 2. Решения заказчика

- Типы работ поровну: лендинги/промо и продуктовые UI/каталоги → два режима моушна, выбор по жанру в §2.
- Стек следует стеку проекта: статика → CSS + при несущем скролле GSAP ScrollTrigger + Lenis; React → Framer Motion (`motion/react`).
- Библиотека рецептов секций — следующий шаг, сейчас только заготовка.

## 5. B — моушн в протоколе

### 5.1 Режим моушна (в §2 «Направление», после жанра §2аа)

Режим выводится из четырёх строк задачи страницы §1а, не из вкуса:

| Режим | Признак по §1а | Что разрешено |
|---|---|---|
| `кино` | задача страницы — убедить/впечатлить: лендинг, промо, портфолио, кейс | вход героя с хореографией; одно скролл-поведение; фоновое медиа |
| `продукт` | задача — найти/сравнить/ввести/сделать: каталог, форма, дашборд, карточка | вход первого экрана ≤ 400 мс одним движением; подписное микровзаимодействие; никакого скролл-кино |

Если по §1а режим неоднозначен — вопрос заказчику через AskUserQuestion вместе с интервью §1в. Режим записывается в DESIGN.md.

### 5.2 §2м «Сигнатурный момент»

Ровно один на страницу. Записывается в DESIGN.md как три строки: **где** (селектор/секция), **что происходит** (одна фраза без прилагательных), **чем доказывается** (какой кадр контакт-листа `motion.mjs` его показывает).

- `кино`: момент = вход героя (стаггер слов / blur-in / маска-раскрытие) **плюс** одно скролл-поведение из списка: пин с скрабом, липкое медиа с затуханием, параллакс слоёв, скролл-раскрытие текста. Второе скролл-поведение запрещено.
- `продукт`: момент = одно микровзаимодействие, которое отличает продукт: переход состояния (нет в наличии, отправлено), раскрывашка с данными, живой фильтр. Вход первого экрана — одно движение ≤ 400 мс, без стаггера по карточкам.

Всё, что не сигнатурный момент, — тишина: переходы состояний по токену `micro`, без reveal-анимаций на каждую секцию. Существующий запрет «всё появляется одним и тем же fade» сохраняется; к нему добавляется «reveal на каждую секцию — тот же дефект».

### 5.3 Блок `motion:` в DESIGN.md (в `_design-md/spec.md`)

```yaml
motion:
  mode: кино | продукт
  stack: css | css+gsap-lenis | framer-motion
  tokens:
    micro: 150ms      # hover, фокус, переключатели; диапазон 120–180
    enter: 450ms      # вход элемента; 300–600
    scene: 1000ms     # хореография героя целиком; 800–1200, только кино
  easing:
    out: cubic-bezier(0.22, 1, 0.36, 1)      # вход
    inout: cubic-bezier(0.65, 0, 0.35, 1)    # перемещение
    # linear только для скраба по скроллу
  stagger: 60ms       # шаг между словами/элементами; 40–90
  distance: 24px      # дистанция сдвига при входе; 12–40
  properties: [transform, opacity, filter]  # только эти; layout-свойства запрещены
  reduced_motion: конечный кадр мгновенно   # не «выключить», а «показать итог»
  signature:
    where: .hero
    what: слова заголовка входят снизу с blur-in, медиа липнет и гаснет к концу секции
    proof: motion-1440-hero кадры 2–8, motion-1440-scroll кадры 3–10
```

Правила: любая длительность в CSS/JS обязана быть одним из токенов (проба `qa.mjs` это проверяет); `scene` отсутствует в режиме `продукт`.

### 5.4 Стек по проекту (в §5 «Реализация»)

| Проект | Стек | Когда подключать библиотеку |
|---|---|---|
| статический HTML/CSS | CSS transitions, `@keyframes`, `animation-timeline: scroll()/view()` с `CSS.supports`-страховкой | GSAP + ScrollTrigger + Lenis только если сигнатурный момент — пин/скраб |
| React/Next | Framer Motion (`motion/react`): `variants`, `staggerChildren`, `useScroll`/`useTransform` | Lenis допустим для smooth-scroll; GSAP не смешивать с Framer на одном элементе |

Библиотеку тянуть через Context7 (актуальный API), версию фиксировать.

### 5.5 Карта «эффект → скилл» (в `_design-md/skills-map.md`)

| Эффект | Скилл |
|---|---|
| вход слов заголовка | `staggered-word-reveal` |
| раскрытие маской | `masked-reveal` |
| прогрессивное размытие края/медиа | `progressive-blur` |

## 6. C — `motion.mjs`

### 6.1 Интерфейс

```
node motion.mjs <url> <outdir> [--width 1440] [--hero 3000] [--scroll 4000] [--name r15]
```

Выход в `<outdir>`:

- `<name>-motion-<w>-hero.png` — контакт-лист 12 кадров (3×4), по 250 мс, первые `--hero` мс после `warm()`;
- `<name>-motion-<w>-scroll.png` — контакт-лист 12 кадров скролл-прохода;
- `<name>-motion-<w>-reduced.png` — конечный кадр прогона с `reducedMotion: 'reduce'`;
- `<name>-motion-<w>.json` — метрики.

### 6.2 Как работает

1. Контекст Playwright с `recordVideo: { dir, size }` и `reducedMotion: 'no-preference'`. Открыть `url`, `warm()` из `warm.mjs` (те же правила прогрева, что у `shot.mjs`), затем перезагрузка без кэша, чтобы вход героя попал в запись с нулевой секунды.
2. В странице до навигации инжектится счётчик rAF: массив дельт между кадрами. Длинный кадр — > 50 мс.
3. Через `--hero` мс — плавный скролл через `window.scrollTo({behavior:'smooth'})` шагами до конца страницы за `--scroll` мс.
4. Закрыть контекст, получить `.webm`. `ffmpeg` режет кадры `fps=4` за окно героя и окно скролла, `tile=3x4` в контакт-лист. Нет `ffmpeg` → STOP с сообщением (как «провал генерации»).
5. Второй прогон с `reducedMotion: 'reduce'`, кадр на `--hero` мс. Сравнение с кадром 12 контакт-листа героя: по `pixelmatch`-подобному сравнению через `ffmpeg` (`psnr`); PSNR < 30 дБ → «reduced-motion ломает страницу».
6. Метрики JSON: `longFrames`, `maxFrameMs`, `cls` (PerformanceObserver layout-shift за окно героя), `reducedMatch` (PSNR), `videoPath`.

### 6.3 Ограничения

- Только Chromium (как `shot.mjs`).
- Видео пишется в CSS-пикселях без dpr — контакт-лист служит критику, не пиксельной точности.
- Прогрев ленивых картинок — из `warm.mjs`, не дублировать (грабля из LEARNED).

### 6.4 Проверка C

- `selftest.mjs`: запуск `motion.mjs` на `_design-md/example-*` странице через `serve.sh`; ожидаются три PNG и JSON с полями; `reducedMatch` ≥ 30 на странице без анимации.
- Ручная: страница с намеренным `transition: width 2s` даёт `longFrames > 0`.

## 7. D — ось «Motion» и проба

### 7.1 Критик (`design-critic.md`)

- Обязательный набор кадров (директор, §6г) дополняется `*-motion-1440-hero.png`, `*-motion-1440-scroll.png`, `*-motion-390-hero.png`. Отсутствие — «набор неполный», как сейчас.
- Критик читает контакт-лист как раскадровку слева направо, сверху вниз; кадр 1 — момент загрузки, кадр 12 — через 3 с.
- Новый обязательный пункт отчёта «Движение»: одна фраза «что происходит» + балл Motion 1–5 + метка `вижу отчётливо` / `кажется` / `вкус`. Шкала: 1 — движения нет или всё едет одинаково; 2 — движение есть, но читается как дефолт (один fade на всё, bounce, > 1 с); 3 — момент читается, но не удерживает; 4 — момент читается за две секунды и уместен режиму; 5 — момент — причина запомнить страницу.
- Критик по-прежнему не знает режим и замысел; режим он не оценивает — уместность режиму сверяет директор.

### 7.2 Гейт §6б

Ось «Motion» добавляется к шести осям. Балл переписывается из отчёта критика дословно, как Specificity. Порог: `продукт` ≥ 3, `кино` ≥ 4. Ниже порога — итерация; стоп-критерий (а) требует прохода порога.

### 7.3 Проба «движение» в `qa.mjs` и `probes/движение.md`

К существующим проверкам (число длительностей, `transition: all`, > 1 с) добавляются:

- длительность или кривая вне токенов DESIGN.md (директор передаёт `--design DESIGN.md`, проба читает блок `motion:`);
- анимация layout-свойств: `width`, `height`, `top`, `left`, `margin`, `padding` в `transition`/`@keyframes`;
- `.reveal`/`[data-reveal]` с `opacity:0` без правила `.no-js`/`:not(.js)`-страховки;
- в режиме `продукт` — наличие `scene`-длительностей.

Класс провала: как у существующих — красный гейт, `ПРОВАЛОВ 0` обязателен.
